# 0030. Shared-state write contract: atomic replace as the baseline, an advisory lock for read-modify-write, fail open on contention

- **Date**: 2026-08-10
- **Status**: Accepted
- **Tags**: concurrency, cgr, state, fslock, goals

## Context

CGR state lives in two stores with opposite concurrency models, and only one of them is safe.

`.arch/board/events.ndjson` (gitignored, ADR 0014) is an append-only log: `appendEvent` writes one `fs.appendFileSync` line per event, `readEvents` skips torn/partial lines by construction, and `foldEvents` is a pure fold. Concurrent appenders are correct with no coordination at all.

Goal frontmatter under `.arch/goals/**` (git-tracked) is ADR 0003's declared source of truth, and every mutation of it is a lock-free read-modify-write. There is no locking anywhere in archkit — the only atomic write in the codebase is `saveGoalProposal`'s tmp+rename (`src/lib/goals.mjs:3172`), used in exactly one place. The concurrency is not hypothetical: the conductor spawns parallel worktree workers (ADR 0013), several sessions can be open on one tree, and `bin/archkit-stop-hook.mjs` is a separate process spawned at every turn-end in every session.

Four concrete defects follow. This contract exists to close exactly these:

1. **Stop-hook concurrent consolidation.** `consolidateGoals` (`goals.mjs:3290`) reads the day's digest, then per terminal goal copies it to `goals/done/archive/` and `rmSync`s the source, then writes the whole digest back. Two Stop hooks overlapping both delete sources, and the second whole-file write clobbers the first's entries — unrecoverably, because the goal files those entries described are already gone.
2. **`stampGoalFields` lost update.** `stampGoalFields` (`goals.mjs:1435`) is `loadGoal` -> mutate `meta` -> `writeFileSync` of the whole file, and it is the funnel every lifecycle transition passes through. Two concurrent stamps of *different* fields — a lease renewal and a status transition — are last-writer-wins over the whole file, so one field is silently dropped.
3. **Reclaim TOCTOU.** `reclaimExpiredLeases` (`board.mjs:639`) folds the board to compute `leases_expired`, then appends `lease-expired` and stamps `lease: null`. A worker that renews its lease inside that window loses it anyway and its lane is re-dispatched — two workers on one lane.
4. **Reconcile move-under-reader.** `reconcileGoalsLayout` (`goals.mjs:396`) writes the destination then `rmSync`s the source. A concurrent reader enumerating the tree sees the same slug in two places — or, having listed before the write and opened after the removal, gets ENOENT for a goal that exists.

## Decision

Adopt a Tier 1 write contract over `.arch/`: atomic replace as the baseline, an advisory lock for anything multi-step, fail open on contention. `src/lib/fslock.mjs` provides the primitive; the mutators adopt it.

**Scope.** Covered is every writer of shared state under `.arch/` that a second process can reach: `stampGoalFields` and the write/rm pairs behind it (`runGoalComplete`'s archive, `writeGoal`, the status-transition helpers), `consolidateGoals`, `reconcileGoalsLayout`'s move and quarantine, and the goal proposal / loop / queue JSON. Reads are uncovered — they stay lock-free and tolerant.

1. **Atomic replace is the baseline.** Every whole-file write to shared state becomes write-tmp-then-`rename` within the same directory, promoting `saveGoalProposal`'s pid-tagged pattern into the shared primitive. A reader then sees the old file or the new one, never a truncated one; this closes the torn-read half of defect 4 and makes every mutation all-or-nothing. On win32 a replace-rename can lose to an open handle (`EPERM`/`EBUSY`): bounded retry, and a give-up is reported rather than swallowed.
2. **Multi-step mutations hold an advisory lock.** Atomic replace makes each write indivisible; it does nothing for read-modify-write, which is where defects 1-3 live. Any mutation that reads state and writes a value derived from it, or that touches more than one file, holds a lock for the whole sequence. The lock is a lockfile created with `fs.openSync(..., 'wx')` — `O_CREAT|O_EXCL`, an atomic create-if-absent on POSIX and Windows alike — carrying the holder's pid and acquisition time so a holder is identifiable.
3. **One coarse lock per archDir, not per file.** The lock is scoped to the goal tree of a resolved archDir. Per-file locks cannot express `consolidateGoals`'s cross-file invariant (archive-then-delete across N goals plus the digest) without a lock-ordering discipline and the deadlocks that come with it, and these mutations are sub-millisecond writes of small files — contention is rare enough that coarse granularity costs nothing measurable.
4. **Re-read inside the lock.** Holding the lock is not sufficient. A mutator re-reads the file *after* acquiring and applies its delta to what it finds, never to a snapshot taken before acquisition. That rule is what actually closes defect 2, and it is what `reclaimExpiredLeases` needs for defect 3: re-check lease expiry inside the lock, so a lease renewed in the window is observed and the reclaim skipped.
5. **Stale locks break on a TTL, and the break is reported.** A lock older than the TTL is removed and re-acquired by the breaker, which returns the fact that it broke one; a silent break is a bug. TTL is the primary staleness signal, not pid liveness — pids are reused, and a tree can be shared by processes that cannot see each other's process table. The TTL sits well above the longest legitimate mutation (a whole-tree reconcile) and well below a human's patience.
6. **Release on throw.** Acquisition is scoped: the lock releases in a `finally`, so a failed mutation cannot strand it. The TTL is the backstop for process death, not for ordinary errors.
7. **Fail OPEN on contention — but never on the write.** If the lock cannot be acquired within a bounded wait and the holder is not stale, the mutation proceeds *unlocked* and reports that it did. The reasoning: these mutators sit on the Stop hook and on the MCP request path, so failing closed converts a stuck lockfile into a hung turn-end in every session — trading a rare lost update for a total workflow outage. Fail-open's worst case is exactly today's behavior, which is unlocked always; goal frontmatter is git-tracked so a lost update is recoverable from history, and the board is reconstructible by fold. Fail-open degrades to the status quo; fail-closed would invent an outage mode the status quo does not have. This applies to lock ACQUISITION only: if the atomic write itself fails, the mutation fails loudly and does NOT fall back to an in-place write, because that fallback reintroduces precisely the torn write rule 1 exists to prevent.
8. **`appendEvent` is already correct and is NOT to be wrapped.** `board.mjs`'s `appendEvent` writes one small `O_APPEND` line per event, `readEvents` discards torn lines, and the fold is pure — the board cannot lose an event to a concurrent appender. Wrapping it would be a strict regression: it would serialize the system's highest-frequency write behind its slowest (a whole-tree reconcile), put lock acquisition on the Stop hook's hot path, and give the one store that currently cannot lose data a new failure mode. The board stays lock-free and append-only. A future *compaction* or rewrite of `events.ndjson` is not an append and would be covered by this contract.

**Deliberately NOT done: full event-sourcing of status transitions.** Making the board the source of truth for goal status and reducing frontmatter to a derived cache would close these races too. Rejected: it rewrites ADR 0003, whose point is that CGR state is a git-tracked, human-readable, human-editable artifact that survives a context reset and shows up in review, while the board is gitignored per-machine scratch (ADR 0014) and so cannot hold truth that must survive a clone. Every reader — `listGoals`, warmup, the statusline CLI, the digest — would have to be re-pointed at a fold, and `reconcileGoalsLayout`'s premise (status drives placement) inverts. Tier 1 closes all four observed defects at a fraction of that blast radius. If a defect survives Tier 1 that only event-sourcing can close, that is a new ADR with the evidence attached, not a preemptive rewrite.

## Consequences

Easier: every lifecycle mutation gets the same guarantee from one place, so a new mutator inherits safety by calling the primitive instead of re-deriving it. The four defects become testable properties of `fslock.mjs` — mutual exclusion across real concurrent processes, stale-lock breaking, release-on-throw, and a torn write never being observable by a reader — provable in a suite rather than argued at each call site.

Harder / constrained: the contract is an invariant nothing enforces mechanically. A new `writeFileSync` against `.arch/` silently opts out of it and no test fails, so the concurrency suites should carry a source audit for that, in the spirit of the existing silent-success-audit and the Windows path-portability guard. The coarse lock serializes mutations that have nothing to do with each other, which is the price of not writing a lock-ordering discipline. Fail-open makes the contract best-effort by design: under a pathological stale lock the system reverts to today's semantics — correct, since that is where it starts, but it means "locked" is never something a caller may assume, only something it is told.

Most constraining: the lock's scope is the *resolved* archDir, so mutual exclusion is only as good as archDir resolution. ADR 0031 (the archDir resolution contract) is a prerequisite for this one, not a sibling — two processes that resolve different archDirs take different locks and exclude nothing.
